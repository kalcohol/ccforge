Implementation And Contract
---------------------------
The generic path sorts an allocator-rebound table of element addresses and
original indices, then applies its permutation using ADL-aware swaps. The
table uses 16 bytes per element on the tested 64-bit platforms; each cycle of
length k needs k-1 swaps. It adds no ordinary move-constructor requirement to
the existing allocator-relative MoveInsertable/MoveAssignable/Swappable surface.

Small types use a value-copy buffer only when all three trivial-copy traits
hold, the ordinary move operations needed by std::sort are available, and
sizeof(T) <= 16. The raw buffer retains its fancy allocation handle and does
not invoke container-element construction/destruction hooks. Both paths check
the rebound allocation limit before a potentially narrower count conversion.
Generic metadata construction has explicit partial-construction cleanup.

The original comparator instance is referenced by the sorting wrappers.
General monotone-input scans provide linear comparison work for ordered or
equivalent inputs without depending on a library's debug-sort validation.
All comparisons finish before container values are permuted or assigned back.
These are implementation observations, not stronger public exception promises.

D1 is unchanged: after an exception the container is valid, size is unchanged
and there are no leaks; element order and individual values are unspecified.
The original stronger comparator-exception observations and the allocator-only
ADL-swap controls are retained without weakening or renaming their assertions.
The implementation follows textbook indirect sorting and permutation cycles
(Knuth, TAOCP volume 3, section 5.2), not third-party Hive source.

Performance Evidence
--------------------
The common public-API measure_sort.cpp source was compiled against exact
baseline and candidate headers using clang 19/libc++, C++26, -O2 -DNDEBUG.
Processes were pinned to CPU14 (SMT sibling CPU30). Each process performs one
warmup and 31 samples, or 2001 for S7, rebuilding seed-1 inputs outside timing.
Five rounds rotate vector/baseline/candidate order across S1-S8. Every sort
checks key order and the complete payload multiset/checksum. Rebound allocation
peaks are measured separately, excluding resident storage and timing overhead.

The first complete batch was NOISY (S1 vector ratio 1.265023) and is retained.
The second complete batch was selected by the unchanged <=1.15 rule, with
ratio 1.145247. No observations were mixed across batches. Both P0 and P2
numerical gates pass for every workload in that selected batch:

P2 is <=24 B/T for generic metadata, <=sizeof(T)+8 B/T for value copies,
and strictly below the baseline's 32 B/T for both. P3 (S1 candidate/vector)
is 1.0986 and is recorded only. S8 participates in P0 but not P1.

The final-header threshold study measured trivial16 at 55.99 ms with copies
versus 122.24 ms with generic metadata. Trivial32 copies were faster but used
32 B/T, violating the strict improvement requirement; trivial64 copies used
64 B/T for a smaller benefit. The selected limit remains 16. Threshold timing
is study-only and does not replace the selected P0 batch or external P1.

This is shared-machine evidence, not a claim of an exclusively idle CCD.
During the selected batch CPU30 averaged 0.159% active (sampled maximum 1.010%);
other cores sharing L3 had intermittent background activity. Topology, load
averages and per-CPU samples are retained for review. The selected noise ratio
is close to its specified limit; tighter isolation may be requested at review.
Earlier threshold/invalid-batch occupancy must not be substituted for this
selected batch's environment record.

GCC 16 results use the same snapshots and one process per implementation and
workload. They are RECORD_ONLY, not a second five-round admission gate.
P1 remains EXTERNAL_NOT_MEASURED. In particular S7 is 2.297 times its vector
lower bound; neither that ratio nor old calibration estimates establish its
reference-implementation ratio. The reviewer should measure S7 explicitly.

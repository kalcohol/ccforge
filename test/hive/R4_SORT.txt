R4.2 Scope And Design
--------------------
Production changes are confined to
backport/cpp26/hive/detail/bounded_sort.hpp. The two corresponding test files
gain controls; hive.hpp, representation, iteration, public APIs, the R4
integration and measure_sort.cpp are unchanged from dfc2cee.

The independent C++20 kernel retains depth-limited quicksort, explicit scan
bounds, a smaller-side recursion/larger-side loop and an internal heap
fallback. Production insertion threshold remains 24; depth credit is twice
floor(log2(N)). No standard-library sorting/heap implementation is used.
There is no kernel allocation, user-defined construction/assignment or
input-specific benchmark detection.

Insertion now uses bounded element shifts rather than a variable-sized block
move. Nonscalars finish comparisons against a live array slot before copying
bytes, preserving support for deleted copy/move constructors. Scalars keep
the current key in a scalar local while shifting; if comparison throws, the
current hole is restored before rethrowing. The buffer is a permutation on
normal return and exception propagation, not necessarily at every intermediate
scalar callback. Comparators must terminate or throw, produce ordinary Boolean
results, and not modify/invalidate storage or reenter sorting on that range.
No callback-observed slot-identity or scalar representation guarantee is added.

A sampled pivot-equivalent key selects three-way gathering; otherwise the
bounded inward scans omit per-exchange equality checks. Neither choice controls
index bounds, pivot exclusion or progress. Both sides are strictly smaller,
and the existing depth fallback bounds worst-case work. Left equal-region
finalization uses min(equal_left, less), avoiding redundant exchanges.
Distinct/repeated-key controls verify that both specializations actually run.

L5 is a direct behavioral writeback control without editing hive.hpp. A
test-only callback marks ordered scratch immediately before the kernel's
false return; Hive must leave its original elements and structure untouched.
Positive and nested/exception-restoration controls prove that the marker
actually ran and was removed correctly. An isolated ordered-copyback mutant
is rejected. This is not a literal hardware-store counter; ordinary builds
contain neither the callback state nor its branch.

Both Hive scratch paths and allocator handling remain as reviewed in R4.1.
All container comparisons finish before writeback/permutation. D1 is unchanged:
after an exception the container is valid, size is unchanged and there are
no leaks; element order and individual values are unspecified. S-I9 remains
an internally validated property under the stated comparator boundary, not a
new public promise. No third-party sorting/container implementation source or
reviewer experimental source was inspected or imported by the implementer.

Decisions And Implementation
----------------------------
- S1 is a project engineering decision, not a committee resolution. Keep the
  basic sort exception promise and stronger observed comparator-exception
  regression controls. The sorting algorithm is unchanged.
- Exhaust comparator throw positions using a separate full-sort count and a
  fresh input per throw point. Keep copyable throwing-element controls.
- Slots contain aligned payload storage, with a four-byte minimum. A separate
  allocator-owned uint16_t skipfield describes live slots and free runs.
  Dead-run links are read/written as bytes. Iteration follows slot addresses
  within each active block; comparisons remain consistent with traversal.
- The default Scheme S keeps original fancy allocation handles for block,
  payload and skipfield deallocation. All element destruction still uses
  allocator_traits, including custom hooks for trivial element types.
- Tail contraction, run migration/coalescing, constructor rollback, allocator
  bounds and block-list invariants have focused independent controls.
- The hard per-block ceiling remains 65535 and is distinct from total size.
  The defaults are minimum 8 and maximum 4096 for all element types, each
  clamped to the static hard maximum. Allocator and structural bounds also
  apply to allocation. Explicit block limits retain their meaning.
- get_iterator uses checked integer address proposals, then live-slot and
  pointer identity checks. It performs constant candidate work per active
  block, does not search reserved blocks, and has no per-slot fallback scan.
  It assumes flat, order-preserving uintptr_t addresses on the tested ABIs;
  non-flat address models are not supported. Input must still identify a live
  element of the container. Invalid-input end() is diagnostic, not a promise.
- Test-only invariant and lookup hooks are absent from ordinary builds.
  FORGE_HIVE_TEST_HOOKS must be uniform within each linked program. Lookup
  counters are single-threaded instrumentation, not a public API.

Cost Evidence And Outstanding Gates
----------------------------------
Primary protocol: Clang 19/libc++, C++26, -O2 -DNDEBUG; one configuration per
process, one warmup and 31 traversal samples; five interleaved rounds of list,
exact R0 headers and new headers per batch. W1 fills one million values. W2
uses the specified three erase/reinsert rounds with one seeded RNG. W3 sums
to a consumed value; the dense checksum is independently validated.

Three primary matrix batches used identical new-header SHA256:
7751057629081b278196e731fb4128765dc30b9469fffe1fedf65ec1aa700a89
Their R0 headers are byte-exact git archives, not later include overlays.
The earlier baseline-only rehearsal used a comment-only R1 overlay with
identical executable logic; it is not substituted for the exact R0 matrices.

For one million int elements, including unused capacity and block/control
storage, but excluding allocator-internal metadata:

                                      R0 linked core        New skipfield
  Payload slot bytes                              24                    4
  Separate skipfield bytes per slot                0                    2
  Requested live bytes                      24568008              6055736
  Requested bytes per live element         24.568008             6.055736
  Allocation calls                              7825                  763
  Capacity                                  1000192              1003520

B1 (<=8 bytes/int) and B4 (<=7825 allocations) pass deterministically.
The 256/1024/4096/8192 sweep recorded 11737/2953/763/400 allocation calls.
4096 has lower requested bytes than 8192 for this workload and leaves less
unused capacity, while comfortably meeting the allocation budget. Timing
noise prevents claiming that this is a universally fastest default.

The list dense-traversal max/min ratios in the three five-round batches were
2.228210, 2.060615 and 1.645522, all above the 1.15 noise limit. Therefore
ALL timing budgets for these batches remain INCONCLUSIVE, including B2 and B3.
This is deliberately stricter than accepting ratios from noisy batches.
Observed new churn/dense ratios were 1.009244, 0.900890 and 1.055588; these are
descriptive measurements, not passing gates. B5 needs a quieter rerun too.
No B5 exception has been self-approved and no universal list-parity claim is
made. GCC 16 -O2 results are recorded as secondary evidence, without applying
the primary timing budget. Other payloads have measurements, not budgets.

HIVE CORE PREPARATION RECORD -- 2026-11-04

Historical linked-slot baseline record. For the subsequent skipfield branch,
its actual validation and unresolved gates, see SKIPFIELD_PREPARATION.txt.

Status
------
The bounded core-preparation work is complete on work/hive-core-20261104.
This is NOT mainline admission, a complete conformance claim, or a release.
The functional validation revision is 39a1f78. The later cost-probe and record
commits do not change the implementation header. Do not merge this branch as
an already-qualified feature or use its root install as a qualified package.

Implemented Units
-----------------
- Selective, attributed source/test staging on an isolated branch; no shared
  <version> wrapper, native probe registration or root build changes.
- Fixed-bound allocator repair and lawful fancy-pointer test controls.
- An isolated harness with native-absence checks, positive/rejection compile
  controls, multi-TU and normal/mutated independent-model controls.
- Separate contract tests and element-exception structural characterization;
  existing traversal-order expectations and disputed evidence are retained.
- Aggregate max_size separated from the block index ceiling, retaining both
  the existing static allocator clamp and the runtime instance bound.
- Constant-work insertion growth selection, rebound allocator checks and one
  legal-tail planner shared by reserve and shrink_to_fit.
- Three compact slot links with explicit sentinel conversions. Block counts,
  iterator indices and order labels remain wide. No element-storage overlay,
  order relabeling protocol or identity-ordering change was introduced.
- MSVC-compatible constexpr allocator detection and a fresh-query control.

The ordinary per-block hard ceiling is 65535, not 256; smaller allocator or
structural limits still apply. This ceiling does not limit total population
to one block. Static/type-level allocator policy remains an admission topic.

Validation
----------
Each successful final configuration ran 81 runtime cases, 13 compile controls
(9 positive, 4 expected rejection), a multi-TU executable, and paired normal/
mutated model checks. CTest registers four entries, not 81 separate entries.

- Clang 19 / libc++: C++23 and C++26, passed.
- GCC 16 / libstdc++: C++23 and C++26, passed.
- GCC 16 / libstdc++: ASan + UBSan at C++23, passed; both runtime libraries
  confirmed linked. No TSan or concurrent-container correctness claim.
- AppleClang 21 / libc++, arm64: C++23 and C++26, passed.
- MSVC 19.51, x64: configured C++23, passed; CMake uses /std:c++latest here.
  The separate C++26 configuration was rejected by bundled CMake 4.3.1-msvc1
  as an unsupported dialect. It is NOT a passing or skipped-runtime lane.

The original fixed-allocator control, geometric-allocation control and compact
slot-budget control each failed against the corresponding earlier header.
The model mutation failed through its intended model assertion. Sanitizer
cleanliness is supplementary; it is not the distinguishing proof for every
change. The standalone harness installs no files or GoogleTest dependency.

Cost Evidence
-------------
For 1,000,000 int elements on the measured Linux 64-bit ABI, default limits:

                                    Original          Prepared
  Slot bytes                              48                24
  Allocator calls                     250001              7825
  Capacity                           1000000           1000192
  Allocated bytes                   66000072          24568008
  Bytes per live element              66.000            24.568

After erasing half without trimming, the prepared allocation stays 24568008
bytes: 49.136 bytes per live element, not 24.568. Block/control overhead and
unused capacity are included; allocator-internal metadata is excluded.
Measured slot sizes agree across tested Linux, macOS and Windows ABIs:
int/double 24, ordinary 32-byte element 48, align16 element 32, align64 element
128. Over-aligned elements are not promised the ordinary four-byte budget.

The optional cost probe consumes results, checks sums, reports capacity and
takes seven traversal samples per case. Three complete local comparisons were
run. Timing varied materially, and sparse/over-aligned cases were uneven; this
does not establish universal traversal parity with std::list. Memory/layout
and allocation-count improvements are the deterministic acceptance evidence.

Remaining Admission Gates
-------------------------
- S1: decided as project policy on 2026-11-05, not a standards resolution.
  Promise valid structure, unchanged size and no leaks after sort throws;
  element order and individual values are unspecified. Current stronger
  comparator-exception observations remain regression controls and cannot be
  removed without separate review. LWG 4584 does not resolve this question.
- G1: get_iterator address-model portability and lookup work contract.
- Existing wide order-counter/epoch exhaustion policy; compression does not
  shorten the counters, but does not resolve their eventual exhaustion.
- P1: native NONE/PARTIAL/COMPLETE policy, header/version macro discovery,
  public build/install integration and installed-consumer validation.
- Explicit allocator-policy and performance acceptance scope.

These are separate follow-up units. Keep the supplied package and earlier
evidence unchanged; do not apply the rejected S1/global-chain experiment.
